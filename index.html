Incident Triage Agent with Human Approval

An end-to-end triage agent for synthetic vessel and equipment maintenance incidents. The agent searches past incidents, drafts a structured triage proposal, and a deterministic rule check plus an LLM critic verify it before a human approves or rejects it in the UI. Zero auto-approval: every decision is stored with the proposal, so every decision is auditable.

  • Real function calling: tool definitions sent to Groq (gpt-oss-20b), results fed back into the loop
  • Framework-free agent loop plus a LangGraph version of the same loop
  • 38/38 pytest passing, including a live Groq test and a transaction rollback test; 1/1 Playwright end-to-end flow
  • PostgreSQL with a single JOIN list query, Alembic migrations, JWT sign-in, feature branches merged on GitHub

How it works

  1. 1File an incident, stored as Open.
  2. 2Run Triage: the agent searches past incidents and reads the best matches.
  3. 3Proposal validated as JSON, then rule-checked (safety incidents are at least High) and critic-reviewed.
  4. 4A human approves or rejects. Decision and status change land in one transaction.

All 15 seed incidents are synthetic demo data, labelled as synthetic in the repo. No real company data.
